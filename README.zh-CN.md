# JobLander

**[English](README.md) | 中文**

> Multi-agent engine for running a job search.
> 把散落在 9 个工具里的求职信息流，收敛成一套有守卫、有评测的 agent 工作流。

**状态：** v0 实战运行中——web 作战室 + 下述 Agent 全部落地，带 eval harness（全量单测 + 盲评脚本）。架构与决策记录见 [`docs/DESIGN.md`](docs/DESIGN.md)。

**边界：** 本仓库只放引擎与文档（可开源）。个人数据（简历、薪资、pipeline、口径）全部留在私有 workspace，由 `config.yaml`（已 gitignore）指向，永不入库。详见 DESIGN.md §6。

**起源：** 2026 年被裁后的实战项目——边打仗边造，打完仗开源。

## Agent Teams

所有 Agent 无状态：输入上下文包，输出制品或提案；功能靠 workflow 组合，不按功能拆 agent（ADR-9）。**人在环内是拓扑的一部分**：一切对外动作（发消息、写日历、写 source of truth）走提案制，用户是最后一跳。

### 🕵️ 情报队 —— 打之前先看清对面

| Agent | 职责 | 架构 |
|---|---|---|
| **尽调员 Diligence** | 零输入公司尽调：要点卡 + 四段简介（断言带编号来源）+ 逐轮轨迹 | **ReAct 多轮**：计划检索后循环「读正文摘录 → 判五项覆盖（动因/面试/技术栈/薪酬/稳定性）→ 为缺口出新查询」；重复查询滤停、连续落空标死角、抓不到新页止损。质量门：零 LLM 硬检查 + 五维盲评 |
| **调研员 Researcher** | 人喂料调研：URL / 贴入材料 → 逐条带来源与日期的档案 | 单发抽取；纪律：每条证据指得回输入，无来源的推断标低置信 |
| **评估匹配 Analyst** | JD + 素材库 + 尽调档案 + 薪酬信号 → 双分匹配快照 + 按该 JD 提炼轴的雷达 | LLM 判断 + **策略即代码**：底线、折价档等全部是私有 config 里的纯函数参数——判断可解释、可回归 |
| **薪酬调研** | 入池即出带日期的市场 band 报告——先有数字再进对话 | Researcher 证据端 + Analyst 统计端合作 |

### 📝 简历队 —— 单轮直出、两级评审、一个教练

| Agent | 职责 | 架构 |
|---|---|---|
| **Customiser** | 弹药库 + JD + 累积意见 → 公司定制版 | **单轮生成，版式代码化**：定制官只产出结构化内容 JSON，版式与身份（姓名/联系方式）由代码固定渲染——样式漂移与身份编造从构造上不可能。自动多轮改稿环是实验后拆除的：环内无外部新信息，多轮不收敛，只翻倍耗时与成本；改进靠意见持久累积，每版从弹药库+JD+全部历史意见整份重新生成 |
| **Evaluator 二人组** | 质量把关：把「能修的」和「缺料的」分开 | ①**招聘方盲评**——信息集刻意只给简历+JD，模拟对面 HR 视角；②**教练分拣**——对照素材库分 agent 可修 / 需用户补料，纪律「先查库再开口」。按需手动触发，不占生成时间；裁判走独立 eval 档；前置零 LLM 硬检查（敏感口径、PDF 页数——版式已代码固定，无需再比对母版） |
| **简历教练（弹药官）** | 对话式收料：把用户丢进来的信息接住、归类、归档 | 三分类（事实/意见/回话）：事实定点归档到素材库具体条目（提案确认制，只追加不删改）；意见并入持久累积集合，之后每版全量生效 |

### ⚙️ 流程队 —— 把杂活变成草稿和提案

| Agent | 职责 | 架构 |
|---|---|---|
| **Scout / Sourcing 侦察** | 邮件、贴入、多源信号 → 标准化机会提案入池 | flash 档抽取；纪律：查不到就 null，不猜 |
| **Scribe 书记** | 面试转写 / PDF → 字段 + 正文 + 战况提案 | 提案制：审批队列改/批后才入档写回 |
| **Prep 参谋** | 面前 brief：局面判断 + 接下来的打法为主轴，10 分钟读完 | LLM 判断吃全量战况（时间线/JD/尽调/评估/弹药库/playbook），判断依据优先最近时间线上的复盘与对方反馈；**用户金标固化为 eval**（brief_eval：长度预算/不罗列/问答限量/幻觉弹药编号），配额代码侧硬截断；红线只指路不复印；LLM 掉线降级模板骨架 |
| **Coordinator 排期** | 贴入邀约 → 候选时段 → 推荐 + 回复草稿（用户发） | 时段抽取用 LLM，排期判断**纯规则**（对照日历跑约束） |
| **内推匹配** | 人脉地图 → 内推人推荐 + 触达草稿（用户发） | 文本检索 + flash 档选人 |

### 🛡️ 守卫（横切）—— 所有出口产物过检

| Agent | 职责 | 架构 |
|---|---|---|
| **Sentinel 宪兵** | 出口产物统一过检，不设旁路 | 双层：**规则层**拦口径红线与格式；**判断层**（LLM）管规则拦不住的——叙事时机、跨材料一致性、语义漂移 |

### 设计要点

- **循环模式按证据选**：尽调员用 ReAct 多轮——每轮搜索都有外部新信息进来；简历定制单轮直出——环内信息集封闭，自动多轮实测不收敛，先从 ReAct 降到 self-refine、再降到单轮，两步都有 A/B 实验背书（见 `evals/`）。
- **生成 / 评估分离**：两条产线各配独立 Evaluator；裁判独立 `model_eval` 档位 + 盲评随机映射 + 零 LLM 硬检查，三重防同族偏袒。
- **模型三档**：判断用 pro、抽取/匹配用 flash（约 1/25 价格）、裁判用 eval——裁判永不弱于产物档。
- **能省则省**：排期规则、硬检查、口径卡拼装、简历版式渲染等不需要判断的环节零 LLM。
